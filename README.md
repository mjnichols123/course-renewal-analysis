# Course Renewal Analysis

Exploratory data analysis of customer ordering and email outreach behavior around course expiration dates for Modern Training Solutions / Pacific Medical Training.

## Project Overview

This project investigates how customer ordering behavior relates to course expiration dates and email outreach. The goal is to identify patterns that may help improve the timing and frequency of renewal-related customer communication.

The analysis currently focuses on several questions:

- When do customers place orders relative to course expiration?
- How does pre-expiration email outreach relate to subsequent ordering?
- How many pre-expiration emails are associated with the strongest order rates?
- Does the timing of outreach before expiration matter?
- How is ordering activity distributed during the 30 days before and after expiration?
- Are there identifiable periods in the renewal lifecycle where customer activity is especially concentrated?

This repository is intended to contain reproducible analysis so that future analysts can rerun, validate, and extend the work as additional questions or data become available.

## Data Source

The analysis uses the public `published_data` files from the Hugging Face dataset:

`fulldecent/mts_course_renewal_marketing`

The project loads the data programmatically rather than requiring the source data files to be manually stored in this repository.

Three primary tables are currently used:

### `email_blasts.parquet`

Contains customer-level email outreach records and course expiration information associated with those email records.

Important fields include:

- `sent_at`
- `is_large_blast`
- `email_blinded_index`
- course expiration date fields

### `expirations.parquet`

Contains course expiration events.

Important fields include:

- `email_blinded_index`
- `expired_date`
- `course_blinded_index`
- `our_course`

### `orders.parquet`

Contains customer order records.

Important fields include:

- `created_at`
- `email_blinded_index`
- `price`

Customer and course identifiers are blinded.

### Main files

**`analysis.py`**

Main entry point for the project. It loads and cleans the data and runs the current exploratory analyses and visualizations.

**`src/data_loading.py`**

Downloads and loads the published dataset tables.

**`src/data_cleaning.py`**

Performs basic cleaning and type conversion before analysis.

**`src/data_profile.py`**

Generates the Markdown data profile.

**`src/data_summary.py`**

Contains reusable terminal summaries and validation checks.

**`src/exploratory_analysis.py`**

Contains the primary exploratory analyses related to expiration events, orders, email outreach, email frequency, and email timing.

**`src/expiration_window_analysis.py`**

Contains focused analysis of customer ordering behavior immediately around expiration, including the ±30-day expiration window.

Creates and saves figures generated by the analysis.

Contains generated reports, exploratory findings, and figures.

## Running the Analysis

From the root directory of the repository, run:

```bash
python3 analysis.py
```

Depending on the system configuration, Windows users may instead use:

```bash
python analysis.py
```

The script will:

1. Download/load the published dataset tables.
2. Clean and validate the data.
3. Generate terminal data summaries.
4. Analyze ordering relative to expiration.
5. Analyze email outreach frequency and timing.
6. Analyze ordering within the ±30-day expiration window.
7. Generate Markdown reports.
8. Save visualizations to `reports/figures/`.

No manual modification of the source dataset should be required to reproduce the analysis.

## Current Exploratory Findings

The project is still exploratory. Current findings should therefore be interpreted as descriptive associations rather than causal effects.

### Pre-Expiration Email Frequency

Initial analysis indicates that expiration events receiving two pre-expiration emails have substantially higher subsequent order rates than events receiving one email.

Additional emails beyond two have shown relatively limited improvement in the aggregate results examined so far, suggesting a possible point of diminishing returns.

### Pre-Expiration Email Timing

Within the final 30 days before expiration, outreach approximately 15–30 days before expiration is associated with stronger subsequent order rates than outreach occurring during the final seven days.

This suggests that effective outreach may need to begin before customers reach the immediate expiration deadline.

### Ordering Around Expiration

A focused ±30-day analysis identified 10,452 expiration events with an order during this period.

Among these events:

- 69.14% of the nearest orders occurred before expiration.
- 30.86% occurred on or after expiration.
- The median nearest order occurred approximately 4.83 days before expiration.
- The final seven days before expiration contained the largest concentration of nearby orders.
- 69.14% of nearby orders had occurred by expiration.
- 82.65% had occurred by seven days after expiration.
- 89.53% had occurred by fourteen days after expiration.

The order distribution and cumulative distribution figures indicate that purchasing activity accelerates as expiration approaches and is particularly concentrated immediately before expiration.

These results, combined with the email timing analysis, motivate further investigation into whether outreach several weeks before expiration precedes purchasing activity closer to the expiration date.

## Reproducibility Notes

Several considerations are important when reproducing or extending the analysis:

- The source dataset is retrieved from the published Hugging Face dataset.
- Customer identifiers are blinded.
- Expiration events are deduplicated using customer, expiration date, and course identifiers where appropriate.
- Analyses involving orders around expiration should clearly define whether they use all possible order-expiration pairs or a single nearest order per expiration event.
- The ±30-day distribution analysis currently selects the nearest order within the window for each expiration event.
- Email timing groups are descriptive and may contain overlapping expiration events when an event received emails during multiple timing periods.
- Reported relationships between outreach and ordering are observational and should not be interpreted as causal effects without additional analysis.

These definitions should be preserved or explicitly documented when future analyses modify them.

## Continuing the Analysis

Current areas for further investigation include:

- Connecting pre-expiration email timing to the timing of subsequent orders.
- Determining whether outreach 15–30 days before expiration is associated with purchases during the final seven days.
- Comparing email timing and order timing on the same expiration-centered timeline.
- Investigating large versus non-large email blasts.
- Examining whether patterns differ across courses.
- Further analyzing diminishing returns from repeated outreach.
- Extending weekly analysis to the 30 days following expiration.
- Evaluating additional customer renewal behavior around expiration.

New analyses should be implemented as reusable functions within `src/` rather than placing substantial analysis logic directly in `analysis.py`.

## Analysis Principles

When extending this project:

1. Preserve the original published data.
2. Perform transformations programmatically.
3. Keep analysis logic in reusable functions.
4. Document important population and denominator definitions.
5. Save generated figures to `reports/figures/`.
6. Record meaningful findings and limitations in the project reports.
7. Avoid interpreting observational relationships as causal without appropriate evidence.
8. Keep the full workflow reproducible from the repository.
